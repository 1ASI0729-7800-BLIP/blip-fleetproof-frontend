## Hallazgos y correcciones

1. **P1 — Desarrollo escribía en Render.** `src/environments/environment.development.ts:3`. La configuración de desarrollo reutilizaba la URL pública aunque README anunciaba localhost. Se sustituyó por `http://127.0.0.1:3000/api/v1`. Incidente: antes de detectarlo, pruebas automatizadas crearon siete cuentas sintéticas audit-…@example.test, IDs 2–8, y algunos vehículos/reportes vinculados en Render. No se borraron: el usuario indicó continuar exclusivamente en local. La prueba final bloquea Render y usa una copia del dataset. No se registraron datos reales ni se usaron cuentas existentes para esas escrituras. El incidente y la limpieza no ejecutada se consignan en la auditoría general.
2. **P1 — Dependencias con alertas conocidas.** `package-lock.json` de `63b2385`, revisión `README.md:79`. `npm audit` informó 11 paquetes afectados, tres críticos. `npm audit fix --ignore-scripts`, sin `--force`, actualizó dependencias dentro de los rangos existentes; auditoría posterior: cero alertas conocidas. No equivale a certificar seguridad del producto.
3. **P1 — Autenticación y autorización inexistentes en servidor.** `src/app/iam/infrastructure/iam-api.ts:33`, `:54`, `:74`. El cliente descarga hashes y compara SHA-256; la sesión visual es modificable. Se documentó como demo; no se implementó un backend seguro ficticio. Riesgo residual: no usar datos reales, contraseñas reutilizadas ni presentar filtros userId como permisos.
4. **P2 — Hallazgos de fuentes caídas aparecían en UI y PDF.** `src/app/report-management/presentation/views/report-detail.ts:90`; `src/app/report-management/application/pdf-export.service.ts:47`. El dominio los excluía del riesgo, pero presentación/exportación iteraban todos. Ambos ahora filtran por fuente disponible. Regresión de dominio y prueba de reporte sin fixtures verifican incertidumbre; no se certifica disponibilidad oficial.
5. **P2 — Comparación perdía cambios por colisión de IDs y escaladas.** `src/app/report-management/domain/model/vehicle-report.entity.ts:85`; `src/app/report-management/presentation/views/compare-view.ts:80`. Un ID de una fuente suprimía un hallazgo de otra; tampoco se detectaba mayor severidad con el mismo ID. Se compara dentro de cada fuente, incluyendo severidad y descripción; se impiden comparaciones entre vehículos/usuarios distintos y la marca visual usa fuente+ID. Pruebas unitarias incluidas.
6. **P2 — Primer ciclo omitía alertas documentarias.** `src/app/vehicle-monitoring/application/monitoring.store.ts:67`. Solo evaluaba diferencias si existía snapshot previo; ahora también alerta por hallazgos del primer reporte. Pruebas verifican primer ciclo, monitoreo pausado y fallo al guardar alertas sin declarar éxito.
7. **P2 — Cierre sin historial de atención.** `src/app/fleet-management/domain/model/fleet.entity.ts:100`; `src/app/fleet-management/infrastructure/fleet-api.ts:49`; `src/app/fleet-management/presentation/components/case-dialog.ts:146`. El PUT reemplazaba estado/evidencia sin conservar revisiones. Se añadió historial opcional compatible con registros antiguos, copias mediante assembler y vista de historial. Las cuentas con casos antiguos registran un snapshot del estado anterior al editar, no eventos pasados inventados. El cierre sin evidencia continúa rechazándose. Se verificaron cierre, dos revisiones y recarga persistida.
8. **P2 — Guardado tardío contaminaba el estado de otro usuario.** `src/app/shared/application/resource.store.ts:45`. Un guardado iniciado antes de cambiar el filtro podía añadir un registro o error a la lista nueva. Se comprueba el scope antes de actualizar señales; dos regresiones cubren respuesta y error tardíos. Esto no proporciona autorización de servidor ni revierte una escritura ya enviada.
9. **P2 — Fechas inválidas podían romper vistas.** `src/app/shared/application/language.store.ts:19`; `src/app/fleet-management/presentation/views/cases-view.ts`, método `due`. Se detecta fecha no finita y se muestra ausencia de valor en lugar de lanzar RangeError. No se convierte información inválida en una fecha oficial.
10. **P2 — Documentación no reproducible y autores contradictorios.** `README.md:7`, `:25`, `:67`. Se corrigieron host local, instalación reproducible, URL de producción y reparto de contextos para alinearlo al informe; no se reatribuyeron commits.
11. **P3 — Error de formulario podía invadir el siguiente campo.** `src/styles.css:458`. La cuadrícula dejaba solo 4px verticales; se aumentó a 20px para los mensajes de validación. Se conserva el diseño existente.
12. **P2 — Cobertura mínima no acreditaba el negocio.** `src/app/app.spec.ts:1`. La base tenía solo creación de App. Se agregaron regresiones de dominio, assembler, monitoreo y scopes y un recorrido de navegador independiente del código entregable; no se añadieron frameworks de pruebas al proyecto.
13. **P2 — Vigencia y regularización no equivalen a verificación externa.** `src/app/report-management/infrastructure/report-api.ts:79`; `src/app/fleet-management/domain/model/fleet.entity.ts:115`; `README.md:85`. Las fechas de consulta son simuladas; una referencia de texto no es archivo verificado. Se aclararon límites. Requiere backend, reglas de vigencia y validación documental para convertirse en una función real.
14. **P3 — Riesgos de operación y configuración de organización.** No existe una rama remota develop del frontend ni CI versionado en `.github/`; la rama predeterminada es feature/sprint2. Esto no demuestra por sí solo pérdida de trabajo. Cualquier reorganización, protección o despliegue requiere revisión del equipo y autorización; no se cambió remotamente.
15. **P3 — Avisos de optimización del build.** `src/app/report-management/application/pdf-export.service.ts:10` y parser CSV cargan bibliotecas con dependencias CommonJS. Build pasa, pero advierte optimización. No se ocultaron los avisos ni se migraron bibliotecas ajenas al curso.
